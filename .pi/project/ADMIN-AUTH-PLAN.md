# Admin Auth Implementation Plan

**Date:** 2026-05-12
**Status:** Approved

## Overview

Add admin authentication to SultanatExplore. Predefined admins only (no registration, no RBAC). Email-based password reset via Resend.

---

## Decisions

| # | Decision | Choice | Why |
|---|----------|--------|-----|
| 1 | Admin scope | Predefined admins only | Small trusted group, no RBAC needed |
| 2 | Seeding | `prisma/seed.ts` script | Explicit, no attack surface from registration |
| 3 | Password reset | Email-based (Resend) | Admin convenience, can re-seed as fallback |
| 4 | Email provider | Resend | Best DX, 100 emails/day free, enough for admin-only |
| 5 | Database | Neon (prod) + Docker Postgres (local) | Neon free tier for prod, Docker for dev parity |
| 6 | Route structure | `/admin/*` | Clean separation from public pages |
| 7 | Dashboard shell | Skip for now | Auth first, shell as separate task |
| 8 | Auth API route | `/api/auth/[...all]/route.ts` | Standard Better Auth convention |
| 9 | Prisma schema | Better Auth CLI generate | Less drift, exact schema Better Auth expects |
| 10 | Session strategy | Server-side + client `useSession()` hook | Server checks for pages, client hook for components |
| 11 | Form library | TanStack Form `useAppForm` + Zod | Pre-bound components, less boilerplate across 3 forms |
| 12 | Field components | Shadcn `Field` + `Input` | New shadcn Field components built for TanStack Form |
| 13 | Error display | Form-level banner | Better Auth errors are generic, can't map to fields reliably |
| 14 | Better Auth bundle | `better-auth/minimal` | Excludes Kysely, using Prisma adapter |
| 15 | Route protection | `proxy.ts` (Next.js 16) | Replaces deprecated middleware, Node.js runtime |

## Implementation Steps

### Phase 1: Foundation

1. **Install dependencies**
   ```bash
   pnpm add better-auth @prisma/client @tanstack/react-form zod resend
   pnpm add -D prisma
   npx shadcn@latest add field input button
   ```

2. **Setup Prisma**
   - Init prisma with postgresql provider
   - Run `pnpm dlx auth generate` to inject Better Auth schema
   - Add custom fields to User model if needed (e.g. `name`, `role`)
   - Run `pnpm prisma migrate dev`

3. **Environment variables** (`.env.local`)
   ```
   DATABASE_URL="postgresql://..."
   BETTER_AUTH_SECRET="..."
   RESEND_API_KEY="..."
   NEXT_PUBLIC_APP_URL="http://localhost:3000"
   ```

4. **Better Auth server config** (`src/lib/auth.ts`)
   - Prisma adapter with `provider: "postgresql"`
   - `emailAndPassword.enabled: true`
   - `sendResetPassword` callback via Resend
   - Export `auth` instance + `handlers`

5. **Better Auth API route** (`src/app/api/auth/[...all]/route.ts`)
   - Export `{ GET, POST }` from `toNextJsHandler(auth)`

6. **Better Auth client** (`src/lib/auth-client.ts`)
   - `createAuthClient` from `better-auth/react`
   - Export `authClient`

### Phase 2: Form Setup

7. **useAppForm setup** (`src/lib/form.tsx`)
   - `createFormHookContexts()`
   - `TextField` component (consumes `fieldContext`, renders Field + Input + error)
   - `SubmitButton` component (consumes `formContext`)
   - Export `useAppForm`

### Phase 3: Auth Pages

8. **Login page** (`src/app/admin/login/page.tsx`)
   - `LoginForm` component using `useAppForm`
   - Zod schema: email + password
   - Calls `authClient.signIn.email()`
   - Redirect to `/admin/dashboard` on success

9. **Forgot password page** (`src/app/admin/forgot-password/page.tsx`)
   - Form with email field only
   - Calls `authClient.forgetPassword({ email, redirectTo: "/admin/reset-password" })`
   - Show success message (email sent)

10. **Reset password page** (`src/app/admin/reset-password/page.tsx`)
    - Form with new password + confirm password
    - Reads token from URL search params
    - Calls `authClient.resetPassword({ newPassword, token })`
    - Redirect to `/admin/login` on success

11. **Dashboard page** (`src/app/admin/dashboard/page.tsx`)
    - Server component
    - `auth.api.getSession({ headers: await headers() })`
    - Redirect to `/admin/login` if no session
    - Render placeholder text

### Phase 4: Middleware + Seed

12. **Proxy** (`src/proxy.ts`)
    - Next.js 16 replaces `middleware.ts` with `proxy.ts`
    - Export `proxy` function (not `middleware`)
    - Node.js runtime (not edge) — can use `cookies()` directly
    - Protect `/admin/dashboard` — redirect to `/admin/login` if no session cookie
    - Redirect `/admin/login` → `/admin/dashboard` if already authenticated
    - Allow `/admin/forgot-password`, `/admin/reset-password` through

13. **Seed script** (`prisma/seed.ts`)
    - Create admin user with email + hashed password
    - Use Better Auth's password hashing or `bcrypt`
    - Run via `pnpm prisma db seed`

14. **Prisma seed config** in `package.json`
    ```json
    { "prisma": { "seed": "npx tsx prisma/seed.ts" } }
    ```

## Edge Cases

- **Token expiry**: Better Auth handles reset token expiry. Default is 1 hour.
- **Concurrent sessions**: Better Auth supports multiple sessions per user. Fine for admin.
- **CSRF**: Better Auth handles CSRF protection out of the box.
- **Rate limiting**: Not in scope. Admin-only, low attack surface. Add later if needed.
- **Error handling**: Better Auth errors shown as form-level banner below submit button. Not mapped to individual fields.

---

## Out of Scope

- Admin dashboard shell/layout design
- RBAC / role management
- User registration
- Social login / SSO
- Two-factor authentication
- Rate limiting
